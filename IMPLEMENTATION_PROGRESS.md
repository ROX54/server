# CyberGarden AI — ход реализации

## Этап 1. Анализаторы, отчёты и тесты

**Статус на 21 ноября 2026 года** — завершён.

- Создана резервная копия затронутых исходников, документации и предыдущих конкурсных отчётов в `implementation-backups/stage-1-before/`.
- Конкурсный запуск в CLI и Dashboard использует собственные SECRET, SAST и SCA. Внешние сканеры доступны отдельно через экспериментальный CLI. AI-объяснение карточки вызывается отдельно.
- SECRET распознаёт литералы, секретные значения по умолчанию и ограниченный поток данных от строковых фрагментов до Bearer-заголовка. SAST использует признаки Kotlin/Spring и JDBC, включая сопоставление контроллера с чтением объекта. SCA обрабатывает декларации Gradle, локальные версии, свойства, lockfile и диапазоны справочника. У каждого advisory отдельная запись.
- `security-report/findings.json` и `security-report/report.md` сформированы из одного списка. Проверены относительные пути, допустимые номера строк, обязательные поля и отсутствие проверенных значений секретов. Сверка с эталоном выполняется отдельно и записывается в `security-report/validation.md`. SHA-256 эталона совпал с исходным.
- Реальный прогон Repair Desk дал **TP 15, FP 0, FN 0, Precision 100%, Recall 100%, F1 100%**. Найдено пять записей на категорию. Срабатываний на контролях **0/6**. Дополнительных advisory на проверке **0**.
- Проверены изменённые синтетические файлы, границы версий, несколько advisory на зависимость, маскирование, контракт отчёта и HTTP-запуск с экспортом. Из девяти автотестов восемь прошли. Тест создания символической ссылки пропущен из-за прав Windows. Отдельная проверка Windows junction прошла.
- Для проверок использован портативный Python 3.13.7 из временного каталога. HTTP-тест Dashboard прошёл на свободном loopback-порту. Стандартный порт 8765 был занят во время проверки `START-DASHBOARD.bat`. Скрипт запуска сохранён.

Границы текущей реализации: результаты измерены на предоставленном эталоне. SAST использует ограниченные эвристики вместо полного анализа межпроцедурных потоков, а SCA работает с числовыми версиями из учебного справочника. Dashboard сканирует встроенный учебный каталог. Выбор разрешённых репозиториев и сквозной сценарий с редактором, расписанием, AI Analysis и webhook относятся к следующим этапам.

## Этап 2. Визуальный редактор workflow

**Статус на 21 ноября 2026 года** — редактор и хранилище реализованы.

- Резервная копия затронутых файлов находится в `implementation-backups/stage-2-before/`.
- Workflow Builder открывается в Dashboard. Canvas использует HTML, CSS и SVG. Библиотека содержит девять типов нод с параметрами и совместимыми портами. Ноды добавляются перетаскиванием или щелчком. Связь создаётся выбором выхода и входа. Condition поддерживает отдельные выходы True и False.
- Три готовых шаблона открываются как редактируемые графы. Сохранение записывает версионированный JSON с координатами, параметрами и связями в `workflow-data/`. Выбранный сохранённый граф запоминается в браузере. Сервер проверяет структуру, порты, параметры, триггеры, достижимость и отсутствие циклов.
- API и модель графа пригодны для передачи следующему исполнителю. Интерфейс редактирует и проверяет графы. Запуск расписаний, AI Analysis и webhook относится к следующим этапам.
- Запущены тесты `test_contest_pipeline` и `test_workflow_builder`. Из 16 тестов 15 прошли, один тест символической ссылки пропущен из-за прав Windows. Проверены шаблоны, API сохранения и загрузки, повторное открытие хранилища, обновление записи и отклонение некорректного графа. Синтаксис JavaScript проверен отдельно.
- `START-DASHBOARD.bat` проверен на свободном порту через параметр `--port`, так как стандартный порт 8765 занят. Из запущенного сервера получены страница редактора, 15 конкурсных находок и все три отчёта. Хеши анализатора, эталона и отчётов совпали с исходными.
- Сквозной тест мышью и перезагрузкой страницы в Edge остаётся непроверенным. Computer Use остановил доступ к окну, поскольку не смог определить текущий URL. Проверка хранения выполнена через HTTP и файловую систему.

## Этап 3. Исполнение графа, расписание и история

**Статус на 21 ноября 2026 года** — исполнитель, API, планировщик и панель запусков реализованы.

- Резервная копия затронутых файлов находится в `implementation-backups/stage-3-before/`. Формат графов этапа 2 сохранён. Старые интервальные триггеры загружаются с выключенным расписанием до явного включения.
- Исполнитель загружает сохранённый граф. Он повторно проверяет его, выполняет активные ноды в топологическом порядке, объединяет находки без дублирования и выставляет статусы нод. Condition поддерживает наличие, счётчики, категорию, серьёзность и ограниченный regex. Для каждого сканера предусмотрен тайм-аут. Ноды вызывают только соответствующие собственные сканеры на `training-project/`.
- Ручные и запланированные запуски получают отдельные идентификаторы. SQLite сохраняет результаты, время, ошибки и состояния последних 60 завершённых запусков. Остановка сервера прерывает незавершённые запуски. Одна запись расписания на workflow защищает от повторного запуска за тот же момент после перезапуска и очистки истории.
- Планировщик поддерживает ежедневный и интервальный режимы, включение и выключение и показ ближайшего времени. Для IANA необходима база часовых поясов. UTC и фиксированные смещения доступны без неё. Пропущенные минуты после выключения сервера не восполняются.
- Report Generator выдаёт JSON и Markdown по одному набору входных находок. Отчёты каждого запуска доступны отдельно от файлов этапа 1. AI Analysis и HTTP Webhook Notification отмечаются как пропущенные при достижении этих нод до интеграции на этапе 4.
- Запущено 28 автоматических тестов. Прошло 27. Тест символической ссылки пропущен из-за прав Windows. Проверены обе ветки с присоединением к общей ноде, отсутствие входа, исполнение выбранных сканеров, объединение находок, история после перезапуска, повторный ручной запуск, отклонение циклов и сложных regex. Реальный фоновый планировщик при контролируемом времени запустил SECRET Scanner, получил пять находок и не продублировал запуск после перезапуска.
- `START-DASHBOARD.bat` проверен на свободном порту во временной копии проекта. Через HTTP сохранён и выполнен Quick Security Scan. Получено 15 конкурсных находок и оба отчёта, а старый отчёт валидации доступен. Хеши анализатора, эталона и конкурсных отчётов совпали с исходными.
- Редактор открылся в Edge. Интерактивную проверку перетаскивания, сохранения, обновления страницы и запуска прервал ввод пользователя в окне. Playwright в доступной среде отсутствовал. Проверены синтаксис JavaScript и серверный сценарий без заявления о полном браузерном тесте.

## Этап 4. AI Analysis и HTTP Webhook Notification

**Статус на 21 ноября 2026 года** — интеграции реализованы и проверены в локальном HTTP-сценарии.

- Резервная копия затронутых файлов находится в `implementation-backups/stage-4-before/`.
- AI Analysis работает с метаданными реальных находок. Ответ проверяется по схеме, ID, пути, диапазону строк и advisory. Описание и рекомендации анализаторов, фрагменты исходников и секретные значения не передаются модели. Провайдер и модель задаются окружением или `.env`. В Dashboard есть проверка соединения, сообщения об ошибках и просмотр валидированного анализа.
- Webhook использует профиль с сервера. Внешние адреса требуют публичного HTTPS, DNS-адрес проверяется и закрепляется за подключением, перенаправления не выполняются. Исключение для демонстрации явно включает профиль `demo` и один endpoint на `127.0.0.1`. HTTP 2xx подтверждает доставку. В результатах показываются код, число попыток и распознанное подтверждение получателя.
- Condition управляет доставкой. При включённом продолжении после ошибки AI нода остаётся ошибочной, а следующие ноды получают только реальные результаты анализаторов. Отправленный webhook в этом сценарии содержит статус ошибки и детерминированную сводку.
- В изолированной копии `START-DASHBOARD.bat` запустил Dashboard. Проверены обе цепочки, с прямой передачей из AI Analysis и через Report Generator. Запущенный отдельным процессом демонстрационный приёмник получил два JSON-уведомления, в каждом было 15 находок и 2 критические. Доставка подтверждена HTTP 200 и совпадением runId. JSON и Markdown получены через API.
- AI HTTP-контракт проверен на локальном тестовом провайдере `integration-test-double`. Реальная LLM не запускалась. Ollama на порту 11434 был недоступен, параметры облачного провайдера в окружении отсутствовали. Поддерживаются OpenAI-совместимый API и локальный Ollama. Доставка на внешний HTTPS-контур и полный браузерный сценарий в этом этапе не проверялись.
- Из 34 автотестов 33 прошли. Тест символической ссылки пропущен из-за прав Windows. Проверены отклонение неподтверждённых ID, координат и advisory, фильтрация данных, ветвление, подтверждение доставки, 4xx, 5xx, перенаправления, тайм-ауты и SSRF-проверки. Хеши анализатора, эталона и отчётов предыдущих этапов совпали с исходными.

## Этап 5. Live Execution, история и интерфейс

**Статус на 21 ноября 2026 года** — интерфейс и серверные изменения реализованы. Проверки с настоящей LLM и полный браузерный сценарий пока открыты.

- Dashboard получил единую тёмную палитру с cyan и purple, а распределение критичности строится по реальным находкам. В Workflow Builder добавлены масштаб 50–160%, режим панорамы, подсветка совместимых портов и обозначение неактивной ветки.
- Статусы и длительность нод поступают из истории выполнения. При выборе ноды видны реальные входные и выходные порты, число находок по категориям, количество AI-сводок и ошибки. Сводка передачи внутри графа не содержит исходный код, значения секретов или параметры подключения.
- Раздел «История» использует существующий SQLite. В нём доступны фильтры по статусу и дате, сведения о нодах, результаты AI и webhook, JSON и Markdown. Экспорт находок доступен и для графов без Report Generator. Архивирование сценария требует подтверждения и сохраняет историю.
- Из 36 автотестов прошли 35. Тест символической ссылки пропущен из-за прав Windows. Синтаксис обоих JavaScript-скриптов проверен. В изолированной проверке Windows-запуск и HTTP подтвердили 15 находок, события исполнения и экспорт. Сверка учебного проекта сохранила 15 TP и 0/6 ложных срабатываний на контрольных примерах.
- Сервер подтвердил отсутствие настроенного AI-провайдера. Локальный Ollama на порту 11434 не ответил. Реальная модель не тестировалась. Для проверки нужен запущенный Ollama с установленной моделью или облачный API, настроенный локально через `.env`.
- Полный сценарий в Edge не выполнен. Computer Use остановил взаимодействие, поскольку не смог определить URL окна. Playwright в доступной среде отсутствовал. Резервная копия находится в `implementation-backups/stage-5-before/`. Копии `submission/server` и `submission/client` не обновлялись и публикация в этом этапе не запускалась.
