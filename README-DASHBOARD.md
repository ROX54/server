# Cyber Garden — AI Security Workflow

Локальная панель для учебного проекта Repair Desk. Конкурсный режим запускает собственные статические анализаторы SECRET, SAST и SCA. По запросу из карточки находки доступно отдельное AI-объяснение.

## Запуск панели

### Windows

1. Установите Python 3.10+.
2. Запустите `START-DASHBOARD.bat`.
3. Откройте <http://127.0.0.1:8765>.
4. Если нужны AI-объяснения, настройте провайдера в `.env` по образцу `.env.example` и перезапустите панель.

При занятом порте запустите `START-DASHBOARD.bat --port 8766` и откройте <http://127.0.0.1:8766>.

### Linux / macOS

```bash
cp .env.example .env # optional AI configuration; edit .env
./START-DASHBOARD.sh
```

Для локальной AI-модели установите Ollama, скачайте модель (`ollama pull qwen2.5:7b`, например), затем укажите в `.env`:

```dotenv
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_API_KEY=
OPENAI_MODEL=qwen2.5:7b
```

Для облачной модели задайте `OPENAI_BASE_URL`, `OPENAI_API_KEY` и `OPENAI_MODEL` провайдера с совместимым `/chat/completions` API. Ключ не нужно и нельзя записывать в исходный код.

## Workflow Builder

1. Перетащите ноды из библиотеки на рабочее поле. Щелчок по названию в библиотеке также добавляет ноду.
2. Для связи нажмите выход исходной ноды, затем вход целевой. У Condition отдельные выходы **True** и **False**.
3. Перемещайте ноды за заголовки. Щелчок по ноде или линии открывает свойства и кнопку удаления. Клавиша Delete удаляет выделенный элемент вне поля ввода.
4. Назовите граф и нажмите «Проверить» или «Сохранить». Сохранённый граф можно выбрать в списке. После перезагрузки страницы редактор открывает последний выбранный сохранённый граф.
5. В списке шаблонов доступны Quick Security Scan, Full Security Audit и Critical Findings Alert. Редактирование шаблона создаёт отдельный граф.

Сценарии хранятся как локальные JSON-файлы в `workflow-data/`. Формат версии 1 содержит типы, параметры, координаты и идентификаторы портов. Webhook хранит имя профиля получателя. Сканирование Repair Desk по-прежнему доступно на вкладке «Сканирование».

### Запуски и расписание

- На рабочем поле используйте кнопки масштаба и «Панорама». В режиме панорамы перетаскивайте свободную область. Выход ноды подсвечивает совместимые входы. Выберите ноду, чтобы увидеть её параметры, статус и сводку переданных данных.
- Раздел «История» показывает имя сценария, время, статус, длительность и число находок. Доступны фильтры по статусу и локальной дате. Откройте запуск для просмотра нод, AI-анализа, доставки и скачивания JSON и Markdown.
- Кнопка «В архив» запрашивает подтверждение и переносит граф в `workflow-data/archive/`. История уже созданных запусков сохраняется. Восстановить граф можно переносом его JSON обратно в `workflow-data/` при остановленном Dashboard.
- Нажмите **Run** после сохранения графа. Для запуска используются Manual Trigger. Если граф содержит только Schedule Trigger, Run выполнит ручную проверку от этих триггеров. Параметры расписания при этом сохраняются.
- Condition проверяет наличие, количество, категорию или серьёзность находок и передаёт входной набор в выбранную ветку. Regex работает по значениям категории и серьёзности. Сложные регулярные выражения, например с повторением групп или обратными ссылками, отклоняются перед запуском.
- Для ежедневного режима укажите время в формате `ЧЧ:ММ`, часовой пояс или фиксированное смещение и включите Schedule Trigger. Например, для московского времени можно использовать `UTC+03:00`. Имена IANA требуют установленной базы часовых поясов. На панели показано следующее время в часовом поясе браузера. Планировщик работает при запущенном Dashboard. Пропущенные минуты после выключения сервера не восполняются. Повтор одного запланированного момента блокируется и после перезапуска.
- Панель запусков показывает состояние каждой ноды, выбранную ветку, время, ошибки и результаты. Report Generator выдаёт отдельные JSON и Markdown для каждого фактического запуска. История хранит последние 60 завершённых запусков в `workflow-data/runs.sqlite3`. Незавершённые запуски при восстановлении помечаются как прерванные.

### AI Analysis

В разделе «AI-провайдер» видны конфигурация, модель и результат реальной проверки подключения. Параметры провайдера читаются из окружения и `.env` при запуске. Для локального Ollama укажите его совместимый API и запущенную модель. Для OpenAI-совместимого облачного API задайте адрес HTTPS, имя модели и ключ в окружении. Конкурсное сканирование доступно без AI.

AI Analysis получает разрешённые метаданные найденных проблем. Ответ проверяется по JSON-схеме, идентификаторам, путям, номерам строк и advisory. Раздел «Запуски» показывает сводку, объяснения и рекомендации. Если модель недоступна или нарушает схему, нода фиксирует ошибку. Опция «Продолжить с находками при ошибке AI» передаёт исходные результаты дальше вместе с общим статусом ошибки. Отчёт и уведомление при этом могут состоять из данных анализа без AI-рекомендаций.

### Локальный webhook

1. Запустите приёмник в отдельном окне командой `py -3 webhook_receiver.py` на Windows или `python3 webhook_receiver.py` на Linux и macOS. Он слушает `127.0.0.1:8767/webhook`.
2. Добавьте следующие параметры в `.env` и перезапустите Dashboard.

   ```dotenv
   CYBERGARDEN_WEBHOOK_ALLOW_LOOPBACK_DEMO=1
   CYBERGARDEN_WEBHOOK_DEMO_PORT=8767
   CYBERGARDEN_WEBHOOK_PROFILES={"demo":{"url":"http://127.0.0.1:8767/webhook"}}
   ```

3. Создайте граф **Manual Trigger → SECRET → SAST → SCA → Condition → AI Analysis → Report Generator → HTTP Webhook Notification**. Соедините выход True с AI Analysis, оставьте условие «Критических находок > 0» и профиль webhook `demo`. Для доставки при недоступной модели включите продолжение при ошибке AI.
4. Сохраните и запустите граф. Приёмник напечатает безопасную сводку и вернёт HTTP 200 с подтверждением runId. Статус появится в результатах ноды. Для проверки ветки False установите порог выше числа критических находок и запустите граф повторно.

Профили webhook задаются на сервере. Внешние профили используют публичный HTTPS на порту 443, соединение закрепляется за проверенным адресом DNS, перенаправления отклоняются. При необходимости задайте в профиле `tokenEnv` с именем переменной `CYBERGARDEN_WEBHOOK_TOKEN_*`. В графе хранится только имя профиля. Временные ошибки дают до трёх попыток с одним ключом идемпотентности на ноду. Подтверждение доставки требует HTTP 2xx. Payload содержит текущий статус запуска на этапе уведомления. Итоговый статус виден в истории после завершения.

## Что делает система

- Кнопка сканирования запускает собственные анализаторы SECRET, SAST и SCA на `training-project/`. Для анализа достаточно файлов проекта.
- После сканирования валидатор сверяет результаты с эталоном и контролями. На вкладке «Сканирование» показаны TP, FP, FN, Precision, Recall и F1.
- Gitleaks, Semgrep и OSV-Scanner доступны через отдельный экспериментальный CLI `external_scanners.py`. Его отчёт сохраняется отдельно от конкурсных результатов и метрик.
- AI-помощник объясняет выбранную находку из её метаданных по отдельному запросу в карточке.

## Файлы отчётов

- `security-report/findings.json` — конкурсный JSON.
- `security-report/report.md` — Markdown по тому же набору находок.
- `security-report/validation.md` — отдельная сверка с эталоном, контрольными примерами и список дополнительных advisory для проверки.
- `security-report/external-findings.json` — отдельный экспериментальный отчёт.

## Ограничения и безопасность

- AI-вызов передаёт только метаданные находки стороннему провайдеру, если выбран облачный endpoint. Для приватной работы используйте локальный Ollama.
- Панель слушает только `127.0.0.1`. Не публикуйте её в интернет без аутентификации, CSRF-защиты и дополнительного hardening.
- Результаты анализаторов требуют ручной проверки; наличие находки не доказывает эксплуатируемость, а отсутствие находок не доказывает безопасность.
