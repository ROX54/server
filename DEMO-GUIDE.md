# CyberGarden AI · репетиция и запись

## Проверенный результат

В живом запуске **Full Security Audit - AI 15** модель Groq `openai/gpt-oss-20b` вернула валидированный JSON для **15/15** находок за **4,22 с**. Весь сценарий занял **5,69 с**, webhook подтвердил доставку ответом **HTTP 200**. В Edge открыты все 15 карточек рисков и рекомендаций. Идентификатор запуска `3ae70175da754ec39ba8acf149a28b1e` относится к локальной истории демонстрационного компьютера.

## Подготовка на Windows

1. Склонируйте [server](https://github.com/ROX54/server) и [client](https://github.com/ROX54/client) в соседние каталоги. Для запуска нужен Python 3.10 или новее. Команды ниже выполняются из `server`.
2. Если локального `.env` ещё нет, создайте его командой `Copy-Item .env.example .env`. Проверьте, что в файле остался один набор настроек провайдера. Храните ключ в этом локальном файле или в переменной окружения и закройте редактор перед записью.
3. Создайте ключ Groq и настройте локальный `.env`. [Groq Console](https://console.groq.com/keys)

   ```dotenv
   OPENAI_BASE_URL=https://api.groq.com/openai/v1
   OPENAI_MODEL=openai/gpt-oss-20b
   OPENAI_API_KEY=YOUR_GROQ_KEY
   ```

   Для Ollama установите приложение, запустите его и скачайте выбранную модель. [Настройка Ollama](https://docs.ollama.com/api/openai-compatibility)

   ```dotenv
   OPENAI_BASE_URL=http://127.0.0.1:11434/v1
   OPENAI_MODEL=qwen2.5:7b
   OPENAI_API_KEY=
   ```

   Для облачного OpenAI-совместимого провайдера вместо этого укажите его HTTPS-адрес API с `/v1`, доступное имя модели и выданный ключ. Провайдер должен поддерживать `/chat/completions` и режим JSON.

4. Раскомментируйте в `.env` три настройки профиля `demo` из [.env.example](.env.example). В первом окне PowerShell запустите `py -3 webhook_receiver.py`. Приёмник слушает `127.0.0.1:8767`. Во втором окне запустите `./START-DASHBOARD.bat` и откройте [Dashboard](http://127.0.0.1:8765). После изменения `.env` перезапустите Dashboard.
5. В редакторе workflow нажмите «Проверить подключение» в разделе AI. Затем проверьте ответ в сценарии. Проверка соединения подтверждает доступ к модели. Для демонстрации структурированного анализа дождитесь статуса **success** у ноды AI Analysis и откройте её результат. Если локальная модель отвечает слишком долго, сократите число находок для AI до одной или двух и повторите прогон до записи.

## Запись экрана на 80 секунд без микрофона

Перед записью откройте Dashboard в Edge, установите масштаб браузера 100% и включите полноэкранный режим клавишей `F11`. Нажмите `Win+G`, выключите микрофон в панели «Захват» и закройте оверлей. `Win+Alt+R` начинает и останавливает запись. Закройте терминалы, редактор `.env` и посторонние вкладки. В Workflow Builder откройте сохранённый **Full Security Audit - AI 15**. При первом запуске из чистой копии сохраните шаблон **Full Security Audit** под этим именем, выставив 15 в поле «Максимум находок для объяснения» и отключив продолжение после ошибки AI. Оставьте поле учебного репозитория пустым.

1. **0:00–0:08.** Начните запись на вкладке «Обзор». Задержите курсор возле 15 находок и распределения по категориям.
2. **0:08–0:22.** Откройте Workflow Builder и покажите цепочку от Manual Trigger через три сканера и Condition до AI Analysis, отчёта и webhook. Нажмите **Run** около 0:16.
3. **0:22–0:34.** Покажите завершение сценария и откройте «История». Выберите самый свежий успешный запуск и задержитесь на списке нод.
4. **0:34–0:56.** Прокрутите до **AI Analysis**. Покажите модель `openai/gpt-oss-20b` и счётчик «15 из 15 находок». Раскройте одну карточку SAST и одну карточку SCA, задержитесь на строках «Исправление».
5. **0:56–1:10.** Покажите ссылки «Скачать JSON» и «Скачать Markdown», затем строку **HTTP 200** у webhook. Откройте блок «Находки запуска (15)».
6. **1:10–1:20.** Вернитесь в «История», покажите успешный запуск с 15 находками и остановите запись. При сетевом сбое откройте предыдущий успешный прогон в истории. Он содержит реальный ответ Groq и квитанцию webhook.

Xbox Game Bar сохраняет MP4 в папке `Видео\Captures`. [Горячие клавиши и расположение записи](https://support.microsoft.com/ru-ru/accessibility/windows/use-a-screen-reader-to-record-your-screen-with-xbox-game-bar).

## Ручная проверка демонстрации

1. В редакторе выберите **Full Security Audit**. Граф последовательно запускает SECRET, SAST, SCA, затем Condition. Условие направляет ветку **True** к AI Analysis, Report Generator и HTTP Webhook. В редакторе можно добавить второй Report Generator и соединить его с выходом **False**, чтобы на экране были видны обе ветки.
2. Перетащите дополнительную ноду из палитры. Проверьте линию подключения, измените заголовок основной ноды Report Generator и сохраните сценарий. Обновите страницу. Проверьте, что сохранились позиция, связь и заголовок.
3. Для надёжной записи оставьте поле учебного репозитория пустым. Это запускает встроенный Repair Desk. Для отдельной проверки ввода вставьте `https://github.com/TBagirov/training` и повторите запуск. При импорте применяется закреплённый SHA. История показывает состояние импорта.
4. Нажмите **Run**. Откройте Condition и проверьте **True**. В «Истории» выберите завершившийся прогон. Сверьте количество находок, откройте результат AI и квитанцию webhook. Успешная доставка имеет HTTP 200 и принятый `runId`. Скачайте JSON и Markdown.
5. Для демонстрации отказа переключите AI на недоступную модель и повторите прогон с опцией продолжения после ошибки AI. Покажите фактический статус ошибки AI, отчёт сканеров и квитанцию получателя. Сводка в этом режиме составлена из данных сканеров.

Для автоматической репетиции выполните `py -3 -m pip install playwright` и `py -3 e2e_demo.py` с установленным Edge. Сценарий запускается в отдельном профиле с временной базой, настоящим локальным приёмником и тестовым AI-сервером. [Запуск Edge с Playwright](https://playwright.dev/python/docs/browsers#google-chrome--microsoft-edge)

## Сценарий выступления на 6 минут

### 0:00–0:45 · Что получает команда

«CyberGarden AI объединяет три вида статического анализа в один воспроизводимый процесс. Пользователь выбирает учебный код, задаёт сценарий проверки и получает отчёт с местами находок и рекомендациями. Я покажу это на Repair Desk. В открытом наборе есть секреты в исходниках и конфигурации, ошибки кода и известные уязвимости зависимостей. В истории можно открыть конкретный прогон и увидеть, какая нода сформировала результат, какая ветка сработала и дошло ли уведомление до получателя».

### 0:45–1:40 · Запуск и устройство приложения

«Открываю Workflow Builder и выбираю Full Security Audit. Начинаю запуск кнопкой Run. Frontend состоит из HTML, CSS и JavaScript, backend работает на Python. Сервер хранит графы локально, а историю запусков записывает в SQLite. Он проверяет типы портов и наличие циклов до выполнения. После запуска исполнитель обходит граф по связям. Сканеры и узлы обработки получают данные от активных предшественников. Здесь видно, какой шаг выполняется и сколько находок он передал дальше. По ссылке можно запустить анализ закреплённого снимка разрешённого публичного репозитория. Для демонстрации используется встроенная копия Repair Desk, которая доступна также без сети».

### 1:40–2:55 · Собственные анализаторы

«Первый шаг ищет подозрительные присваивания и секретные значения в Kotlin и конфигурации. В интерфейсе видны тип находки и строка, а значение скрыто. Второй шаг проверяет ограниченный набор шаблонов Kotlin и Spring, например сборку SQL с подстановкой, настройки TLS и правила доступа. Третий шаг читает Gradle Kotlin DSL, разрешает версии по декларациям, свойствам и lockfile и сравнивает их с локальным справочником. Одна зависимость может дать несколько advisory. Конкурсный режим запускает эти три реализации. На предоставленном эталоне они дали 15 совпадений, по пять в каждой категории, и не отметили шесть контрольных примеров. Это результат открытого набора. Перенесённые и переформатированные входы проверены отдельно».

### 2:55–4:15 · Ветки, AI и уведомление

«В демонстрационном условии проверяется, есть ли хотя бы одна критическая находка. Открываю Condition. Ветка True передаёт список ноде AI Analysis. AI получает метаданные найденных проблем и помогает объяснить риски и исправления. Сервер сверяет ответ JSON с исходными идентификаторами, путями, строками и advisory. Показываю результат конкретной модели, если она успешно отработала. При ошибке провайдера Dashboard показывает ошибку. Настройка продолжения позволяет всё равно оформить отчёт из находок сканеров. В конце HTTP Webhook передаёт компактную сводку получателю. Здесь виден HTTP 200, а в окне приёмника тот же идентификатор запуска».

«Открываю текущий прогон в истории и скачиваю JSON и Markdown. Оба формата формируются из одного набора данных. В JSON есть относительные пути, строки для SECRET и SAST и координаты с advisory для SCA. В Markdown эти записи можно изучить визуально. Фильтры истории помогают найти нужный прогон по дате или состоянию. Можно настроить ежедневный запуск в заданном часовом поясе. Планировщик работает вместе с Dashboard и защищён от повторного запуска за тот же момент. В текущем показе выбран ручной запуск».

Результаты измерены на открытом учебном наборе. Для произвольного проекта выводы зависят от языка, правил и базы advisory. Код и инструкции запуска находятся в двух публичных репозиториях.
