# Почему добавлены эти правила

Правила выведены из исходников `training-project/` и безопасных контрольных примеров. Эталон находок при написании правил не читался как список ответов и не подставляется в отчёты сканеров.

## Gitleaks

- `cg26-bearer-in-config` — в `application.yml` есть поле авторизации со схемой `Bearer` и литералом. Соседнее поле читает `${INVENTORY_TOKEN}` без значения по умолчанию; allowlist не даёт сработать на подстановку переменной.
- `cg26-env-fallback-secret` — Elvis-выражение `getenv(...) ?: "…"` оставляет секрет в репозитории. В `RepairAccounts.kt` запасное значение — `UUID.randomUUID()`, это не общий секрет, поэтому такая строка в allowlist.
- `cg26-password-assignment` — идентификатор с ролью пароля получает строковый литерал. Документационный `YOUR_API_KEY` в README исключён.

Конкатенация двух литералов перед `setBearerAuth` не выражается одним регулярным выражением Gitleaks без ложных срабатываний на обрывках. Её ищет правило Semgrep.

## Semgrep

- Интерполяция `$` внутри строки `queryForList` / `query` — SQL-инъекция. Соседний запрос с `?` и отдельным аргументом JDBC не совпадает с шаблоном.
- `HostnameVerifier { _, _ -> true }` отключает проверку имени. Обычный `HttpsURLConnection` без этого присваивания не совпадает.
- Пара `allowedOriginPatterns = listOf("*")` и `allowCredentials = true` в одной конфигурации — credentialed CORS.
- `permitAll()` на пути вне `/api/catalog/` — открытый маршрут к данным, которые не являются публичным каталогом. Каталог услуг оставлен как безопасный пример.
- `jdbc.query` по `ticket_id`, без `customer_id` в том же SQL, при идентификаторе типа `Long` — чтение объекта без проверки владельца.
- Два строковых `val` и их конкатенация, переданная в `setBearerAuth` — секрет, который восстанавливается из исходника.

## SCA

Отдельных пользовательских баз OSV нет. Улучшенный режим добавляет локальную сверку `build.gradle.kts` со справочником `vulnerability-database/`: прямые координаты, константа версии и `gradle.properties`. Совпадения с OSV-Scanner схлопываются по координатам и алиасам CVE/GHSA. Записи OSV, которых нет в учебном эталоне, сохраняются как дополнительные и не помечаются ложными без сверки текста advisory.
